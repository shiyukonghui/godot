## 0. 本批两项（**不新增工具、不改名字**）

### 1. E-9：`project_read_resource` 只回 `{loaded,path,type}` —— **读资源却不给内容**

**现状（M4c 实测）**：`{"loaded":true,"path":"res://cv_d5_b.tres","type":"Curve"}`，**零属性值**；
而同一资源引擎侧 `get_property_list()` 有 **7 个 STORAGE 属性** → 调用方被迫再走一趟
`editor_execute_gdscript` 才能看到内容（**违反 GDR-25 §23.1**）。

**要求**：
1. 在响应里给出资源的**属性值**：取引擎 `get_property_list()` 中**可用（`STORAGE`）**的属性，
   经**既有**的序列化路径（`serialize_variant`，形状按 **§23.4** 规则）输出，**字段命名与既有的读属性工具一致**。
2. **限量**：给出**条数上限**与**截断标记**（避免巨型资源配置把响应撑爆），上限值与截断行为写进报告。
3. **诚实**：资源加载失败/不存在 → `-32001` + `data.suggestion`（沿用既有语义）；无属性 → 空列表 + 说明，**不得**假装有内容。
4. **链式喂回**：报告里给一条实测链 —— 读资源拿到属性（如 `Curve.min_value`）→ **原样**交给
   `project_edit_resource` 或 `editor_set_node_property` 写回（按 **§23.4** 的往返证据形态）。

### 2. E-6 + G-4：日志/错误工具的**来源**与**即时性**

**现状（M4c 实测）**：`editor_read_scene_inspector.cpp` 硬编码 `user://logs/godot.log` 且**只读文件**；
**编辑器端点读到的是游戏进程的行**（`port 9889`、`editor=false`、`source=log_file`）；
轮转窗口里直接 **`-32603`**（**非诚实空**）；而同族的 `editor_remove_output_log` 走**进程内** `EditorLog`
（`editor/editor_log.h:182`）→ **语义分裂**。

**要求（按 §23.3）**：
1. **优先**读**本进程内**的来源（编辑器进程内为 `EditorLog`），**文件仅作后备**；
2. 响应**必须**带 `source`（`editor_log` / `log_file`）与**所属进程**（至少 `editor: true/false`，并给端口或 pid），
   使调用方**不会把别的进程的日志当成自己的**；
3. 不可用 → **诚实空**（`no_results` 语义）或明确 `-32000` + 建议；**不得**用 `-32603` 掩盖；
4. `editor_get_errors` 与 `editor_get_output_log` 的**返回形状统一**（同一组来源字段）。
5. **明确区分**：若「编辑器进程读不到游戏进程日志」属**架构事实**（跨进程），
   报告里要说清「现在能不能读到、经哪条通道、为什么」，并在契约描述允许的范围内**如实**表达；
   需要改描述就**报缺陷**给决策者（你可能需要走 `DESCRIPTION_OVERRIDES`，**由我决定**）。
