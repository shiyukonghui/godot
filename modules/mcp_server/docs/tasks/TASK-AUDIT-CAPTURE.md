## 1. 必须核实（逐项给结论 + 你自己跑出的证据）

### A. **特性的存在理由**（最重要）
1. 自己构造一次「**报成功但什么都没发生**」的调用（例如同一写操作**连做两次**：第二次是同参同值的重放），
   在 `--mcp-capture=every_call` 下必须看到：两次 `error_code` 都是 0，而日志里**第一次 `changed:true`、第二次 `changed:false`**
   （附 `changed_pixel_ratio`、前后 sha256、`seq` 对应关系）。**游戏端点也测一次。**
2. **独立复核那个比率**：自己用 `editor_analyze_screenshot_diff`（或自己写的像素比对）对**同一对文件**算一遍，
   数字必须与日志行**一致**（这是「日志不撒谎」的直接判据）。若你发现它靠的是**日志自述**而非真图，报缺陷。

### B. 三档开关与三个视口
3. `off` 不产图（且**目录不被写**）、`on_error` 只对失败调用产图、`every_call` 全产图 —— 各给证据。
4. `editor`/`2d`/`3d` 三个视口各产一张**有内容**的图（1×1 或全黑视为失败；自己校验尺寸与像素多样性）。

### C. 诚实性与边界
5. `--headless` 下：调用**照常工作**、捕获行 `status:"unavailable"` + `reason` 与既有报错**逐字相同**、**零文件**。
6. 写失败/无帧缓冲**不得**影响工具调用；捕获**绝不进响应**（自己核对响应字节）。
7. 延迟通道（`pending_handler`）的调用记 `unavailable` + `reason`（**不静默 skip**）。
8. **不设上限**：自己证明**没有任何删除路径**（搜代码 + 实跑多次后清点文件数只增不减）；
   `total_bytes` **严格递增**；超阈值**只 WARN 不删**（若能安全构造，自己构造一次）。

### D. 零行为变化（**独立复核**）
9. `pre`（从改动前的提交重建）/`off`/`on` 三跑，探针（含**全量 `tools/list`**）**逐字节相同**、0 不稳定。
10. `on` 时 171 个工具的**响应**逐字节相同；契约 `tools_list.renamed.json` **sha 未变**。

### E. 代价与缩放一致性（TASK-045/046）
11. **缩放一致性**：`scale=2` 下，日志的 `changed_pixels/total_pixels` 必须 == 把**落盘文件**喂给
    `editor_analyze_screenshot_diff` 得到的数字（自己跑，别信报告）。
12. **代价**：自己测 `off` / `every_call`(scale=1) 的**响应耗时**与**背靠背往返**（给方法与分布）；
    核实「响应路径只多一次 framebuffer 拷贝」这一主张（服务端 `duration_ms`），
    以及**背靠背**的实测是否与 §25 第 14 条记的 ~99–101 ms 同量级（**允许机器噪声，但要如实说**）。
13. **等价性**：同一对 PNG 的判定与 `changed_pixels` 在 `scale=1` 下必须仍是 **106800 / 5339554**
    （TASK-044 的锚点数字），且 `editor_analyze_screenshot_diff` 的**整包 payload sha256** 与
    `REPORT-045` 记的 `51c69777…` 一致。

### F. 工程门与端口
14. 六道门自己跑（门① ≥3 组、门② ≥3 个证据脚本、门③④、门⑤ ×2 且 PASS 清单一致、门⑥ 三段式含探针）；
15. **9877 全程未被我们占用**（PID 前后一致或不存在）、测试只用 9888/9889（另开端口收尾释放）、无孤儿、
    **无 git 写操作**、工作树只剩既有未跟踪物。
