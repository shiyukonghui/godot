### 1. `check_narrowing_points.py` 的**引脚索引方式**（修实现，并**更正** REPORT-023 的声称）

**实测事实（TASK-024b 上报，决策者已自行查证）**：该脚本的 `PINNED` 是
**`{file: {line: pin}}` 按行号做键**，且「陈旧条目」是**失败条件** →
因此**任何代码位移都会假红**，每批必须手工重钉（TASK-024b 就把 `851` 改成了 `986`）。
而 `REPORT-023` 的偏离项里**声称**「按 `(文件, 标记 id, 文件内出现序)` 钉、行号只作说明」——
**声称与实现不符**。

**要求**：
1. **真正**改成按 **`(文件, 标记 id, 该标记在该文件内的第 n 次出现)`** 索引；**行号只作为注释/报告信息**，
   位移**不得**导致失败。
2. **失败条件必须保留并仍然有效**：①出现**未标注**的收窄点；②标记 id **不在**清单里；
   ③清单里的条目**在源码中找不到对应**（标记消失了 → 陈旧条目）。
3. **必须用三组实验证明**（各自留证）：
   - **位移不假红**：在不改变语义的前提下**移动**一段含收窄点的代码（或加空行/注释）
     ——**不重钉、仍 PASS**；
   - **新增未标注点仍红**：插入一个裸 `(real_t)` 收窄 → **exit 1**（红演示后回退）；
   - **陈旧条目仍红**：删掉/改掉源码里某个标记 id → **exit 1**。
4. **在报告里显式更正**：说明 `REPORT-023` 的该条声称与实现不符、**实际行为是什么**、
   **现已如何修正**。这是**对已验收报告的勘误**，必须写清（不得悄悄改代码了事）。

### 2. E-3 **写侧**闭合：**每个读回形状必须能被写回**

**实测事实（TASK-024b 披露，未越权修）**：读侧已经统一成对象/数组形状（`v4={x,y,z,w}`、
`pv4=[{x,y,z,w},…]`、`bytes=[1,200]` 等），但**写侧没有 `Vector4i`/`Rect2i` 的分量表** →
**把读回的对象原样写回会被 `-32602` 拒绝**。这**违反 GDR-25 §23.1(1)/(4)**：
「工具返回的标识**不必转形就能喂回**」。

**要求**：
1. 对**读回形状矩阵里的每一项**（`Vector2/2i/3/3i/4/4i`、`Color`、`Rect2`、`Rect2i`、
   以及全部 packed 数组）做**写回测试**：把 `editor_get_node_properties` 读到的值**原样**交给
   `editor_set_node_property`，必须 `code=0` 且 `new_value` 与读回值一致。
2. 对**不能写回**的项：**补齐写侧**（分量表/元素判定，经已有的 `value_fits_slot` 闸门与
   `_check_components`/`_element_fits_container` 路径，**不得**新开绕过闸门的分支）。
3. 若某项**引擎本身不可写**（只读属性、类型不可设），必须在报告里**逐项列出并给出引擎依据**，
   并在工具响应里给出**可读原因**（不得只回一个笼统的 `-32602`）。
4. **门⑥**：新增/移动收窄点按新规则标注。
5. **顺手性自评**：把 TASK-024b 的**零字符串手术链**扩展成**读→写→再读**三段，
   并**逐步标出调用方字符串处理次数（目标 0）**；两端点（9888/9889）各跑一遍。
