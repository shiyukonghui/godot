## 0. 本批两项

### 1. D-8：`OBJECT` 属性的读写**双向闭合**（规范已由决策者落笔：§23.5）

**实测**：`serialize_variant` 对**空 `Object` 指针**答 `{}`；写侧拒 `{}`；写 `null` 读回仍是 `{}`。
**规范（§23.5）**：读回 —— 未设置 → **`null`**（**不得**答 `{}`）；已设置资源 → `{"type","path"}`；
无路径资源 → `{"type","path":""}`（可加 `local_to_scene`）；非资源对象 → `{"type","path"}`，**不泄露指针/地址**。
写回 —— 接受 **`null`** / **`res://` 字符串** / **对象 `{"type","path"}`（与读回同形）**；
`{}` → **`-32602`**；加载失败 → `-32001` + 建议；`type` 不符 → `-32602`（消息给期望与实际）；
写回后**必须读回验证**（§23.4 三层等价），且 `null` 写回后**读回必须是 `null`**。

要求：**跨工具**验证（节点属性路径 + 资源属性路径 + 两端点），并给出「读回值原样喂回」的实测。

### 2. E-2 + E-8：**节点路径**必须是稳定的、相对编辑场景根的、可复用的

**现状（M4c 实测）**：编辑器侧路径一律是**内部绝对路径**
（`/root/@EditorNode@20539/@Panel@14/…/@EditorMainScreen@166/@SubViewport@9998/Main/Actor`），
**场景树工具与 `-32001` 错误消息都用它**，而**成功响应里的 `node_path` 却是相对形式 `"Actor"`**
→ ①语义分裂；②`@EditorNode@<id>` 之类**不可复现**（虽然 M4c 复核「同进程两次与重启后相同」**未能复现"每次运行都变"**，
但它是**编辑器内部布局**的产物，**跨机器/跨布局/跨插件必然漂移**）；③不可跨调用链式使用；
④错误消息里的路径**难以断言**。

**引擎正解（M4c 给出，请自己复核）**：
`scene/main/node.h:573 get_path_to(node, p_use_unique_path)`、`node.h:554` / `node.cpp:2139` `get_unique_scene_id()`
（本 fork 保存 `unique_id=`）。「相对编辑场景根」的稳定路径是创作语义的正确形式。

**要求**：
1. **统一口径**：编辑器侧**所有**对外返回/报错的节点路径，统一为**相对编辑场景根**的形式
   （例如 `Actor`、`Player/Sprite2D`）；需要绝对路径时**另给字段**（如 `absolute_path`），
   **不得**把编辑器内部绝对路径当主字段。
2. **可复现**：同一棵场景树在**两次不同进程启动**下返回**逐字相同**的路径（给出实测两轮的对照）。
3. **错误消息**：不得再出现 `@EditorNode@…`；给出前后对照。
4. **不破坏既有对等**：`tools/list` 与描述**不改**（若你认为需要改描述 → **报缺陷给决策者**，走 override 由我决定）。
5. **影响面必须查清**：受影响的工具清单（场景树、读属性、find_*、信号、错误消息……）逐条列出并给证据；
   同时**回归**：TASK-015/016/017 建立的**写族→读族互验链**必须仍然成立（路径能喂回去）。
6. 若某个引擎 API 只能给出内部绝对路径，**在报告里说明并给出替代方案**，不得静默退回。
