## 1. **D2（最重要，落回本项目核心命题）**：`project_edit_resource` 的成功形状与 `ignored` 语义

M4e/B5 验收实测（`REPORT-AUDIT-B5.md` D2）：
1. `Curve.min_value = 5.0` 被引擎**夹成** `0.99…`，而工具把它**列进 `changed`**、**没有 `ignored` 条目**
   → 违反 **`DESIGN-DETAIL` §20.6**（引擎夹取/忽略的属性**不得**列为已设置，必须进 `ignored` 并给 `requested`/`stored`/`reason`）。
2. **完全未知的属性名**（`no_such_property`）返回**成功形状** `{changed:{}, message:"No properties were changed"}`
   → **既不报错也不点名** → 调用方**无法区分**「这个参数存在但没动」与「**这个参数根本不存在**」。
   这是**本项目要消灭的那一类**（报成功 + 什么都没发生 + 不给可判信息）。
   → **要求**：未知属性名一律 **`-32001` + `data.suggestion`**（点名该属性、提示它不存在）；
   若要保留「批量里部分属性未知」的语义，必须**逐条**在 `ignored` 里点名并给 `reason:"unknown property"`，
   **且**顶层要能让调用方一眼看出「有东西没被写」（例如计数/布尔）。
3. **同类自查（必做）**：**其它资源写工具**（`project_create_resource`、以及 `editor_set_node_property` 家族）
   在「未知属性 / 引擎夹取 / 引擎静默忽略」三种情形下**是否也有同样的成功形状**？
   → **逐条列出并给出实测**；有则一并按 §20.6 修（**同一口径**）。
4. **回归**：本批改动会让**依赖旧成功形状的证据脚本**失败 → **列出受影响清单**并如实修正
   （**不得**为让脚本变绿而放宽断言；TASK-032 已立先例）。

## 2. **D1（low）**：`check_tool_groups.py` 的 `--batch B1` 说法与实际不符

`usage` 写 `[--batch B1|B2|B3|B4|B5]`，但 `--batch B1` 被判 **unknown batch → exit 1**（B1 的不变式实际由**无参数**路径执行）。
→ 二选一：**改 usage 措辞**（写明 B1 = 无参数路径），或**让 `--batch B1` 等价于无参数路径**。
Settle 后**给实测 exit code**。

## 3. **R4（medium，脚本纪律）**：历史证据脚本的 `before` 锚点用 `HEAD`

`mcp034`（109/114）与 `mcp035`（66/67）共 **6 条 `s0_head_*`** 断言读 `git show HEAD:…` 并断言**旧形状** →
随 HEAD 前进**反转**（B5 验收已独立裁决为「脚本陈旧、非实现回归」）。
→ **本批把这类脚本的锚点钉成显式提交**（它们各自任务当时的提交），使结论**不再漂移**；
**断言强度不得削弱**（若某条「before」状态已无法复现，就把它**改写为「记录于提交 X 的快照」**，
而不是删掉或改成恒真）。
**同类普查**：扫描 `scripts/**` 里所有对 `HEAD` 的引用（`git show HEAD:`、`git rev-parse HEAD`、`--version == HEAD` 之类），
**逐条判定**：哪些是**必须**随 HEAD 的（如门前的「二进制绑定 HEAD」检查）、哪些是**必须钉锚点**的（历史对照）→
给出清单与处置。
