## 0. 来源与目标

TASK-020 修掉了 D-1（分量级）与 D-2（`STRING→FLOAT/INT`），并在报告里**主动列出**了**同一缺陷类的残留面**。
决策者裁决：**在 M4 复核之前把同类面一次补齐**——否则复核只会再把它们当新缺陷报一遍。
本任务**只做这一类**（值转换的诚实性），**不新增工具**。

## 1. 要补的面（**先自己复现，再修**；每条都要「修前红 + 修后绿」）

1. **`STRING→BOOL`**：迁移源/现有实现对 `visible="abc"`、`"NaN"`、`" "` 之类的输入是什么行为？
   若会**静默写成 `false`/`true` 并报成功**，按 D-2 同一口径修：**不可解析即 `-32602`**；
   可接受的拼写（如 `"true"/"false"/"1"/"0"`，以引擎语义为准）保留并**在报告里列出**。
2. **容器元素位宽**：`PackedByteArray` / `PackedInt32Array` / `PackedInt64Array` / `PackedFloat32Array` /
   `PackedFloat64Array` 的**元素**是否也走判定？给越界值（如 `PackedByteArray` 元素 `1e20`、`-1`、`300`）
   验证是否被**静默截断/取模**并报成功；若是，按同一口径**拒绝（`-32602`）**或**明确钳制并在结果里标记**
   （二选一，说明理由；**不得**静默）。
3. **`PackedVector4Array` / 其他向量数组的元素整形**：确认每个向量元素的分量都走 D-1 的分量表；
   缺失的按同一机制补上。
4. **顺带自查**：`coerce_to_property_type` / `shape_vector_from_json` / `property_value_from_json` 里
   **还有没有**「转换失败 → 退化成默认值 → 报成功」的路径（自己通读并列出，逐条判定是否需要修）。
   报告里必须给出这份**路径清单**与逐条结论（修 / 不需修 + 理由）。

## 2. 证据形态（继承 TASK-020 的硬要求）

每个面、每个反例都要**同时**给三条：
①**错误码 `-32602`**（或明确钳制 + 结果里标记，仅限第 2 条允许的选项）；
②**前后场景 `.tscn` sha256 相同**（或明确记录钳制后的预期变化）；
③**用另一个读工具**读回并**明确断言旧值未变**（或钳制后的值符合声明）。
覆盖 **整数/浮点/字符串/布尔/复合/数组/容器/dictionary/null** 与**批量路径**。
