## 0. 缺陷（M4d 第四次独立验收 D2，high）

`check_narrowing_points.py` 只认 6 种**字面拼写** `(real_t)`/`(float)`/`Color(`/`Vector2(`/`Vector3(`/`Vector4(`。
M4d 用五个探针实测：**插入后门⑥ 仍 exit 0（扫描器 0 命中）**，而同一数值写成 `(real_t)` 就 exit 1：

1. **隐式收窄**：`const real_t x = 1.0e300;`
2. **`static_cast`**：`static_cast<float>(1e300)`
3. **限定构造**：`::Color(1e300, 0, 0, 1)`
4. **花括号构造**：`Vector3{1e300, 0, 0}`
5. **跨行构造**：`Color` 与 `(` 分行

→ 「新增收窄点必被挡住」这个保证**在拼写层面不成立**（R1：门绿 ≠ 覆盖面完整）。

## 1. 两条路线（**任选其一，但必须实测并说明代价**）

### 路线 A：扩展扫描器覆盖
把上述五种（以及你自己想到的其它等价拼写，如 `static_cast<real_t>`、`(double)`→`real_t` 的赋值、
`real_t x{...}`、`Vector2(` 分行、`Color ` 后跟换行再 `(`）纳入扫描，并**为每一种拼写加「插入即 exit 1」的探针回归**。
注意**误报**（合法加宽、注释、字符串、`#if` 分支）必须处理，并给出**误报率评估**（在**当前树**上跑，必须 exit 0 且 0 误报）。

**范围仅限 `modules/mcp_server/**`**（不得改变引擎其它部分的构建）。
必须实测并报告：①**告警量**（当前树应为 0，否则逐条判定）；②**构建代价**（时间影响）；
③**能否挡住上面五个探针**（每个探针都要有「插入后构建/检查失败」的证据）；④与既有门⑥ 的关系（是否退化为标注一致性检查）。
