# TASK-055 — **给 Godot 源码打补丁（1）**：让 C# 脚本能拿到**真正的编译结论**

> 规范：`DESIGN-DETAIL` **§26/GDR-28 第 13 条**（当前状态：C# 被下调为 `unverifiable`）。
> 报告 `docs/reports/REPORT-055-csharp-compile-verdict-patch.md`。返回决策者的内容**只允许**是「≤8 行总结 + 报告路径」。

## 0. 决策者裁决（用户已授权打补丁）

用户授权：**「某些工具拿不到具体的成功和失败响应」时，可以考虑给 Godot 源码打补丁**。
已确认的第一处根因：`CSharpScript::reload()` **恒返回 OK**（`modules/mono/csharp_script.cpp:2588-2621`），
唯一看似可用的 `valid` 是**私有**且语义是「这个类之前建过吗」（`csharp_script.h:137` + `ScriptManagerBridge.cs:436-463`）
—— **引擎根本没有对外提供「这个 `.cs` 文件编译过吗」的结论**，于是我们的工具只能诚实地答 `unverifiable`。
→ **本批就是把这个结论补出来**：在引擎侧加一个**最小、只读、朝上游形状**的 API，并让我们的工具用它得到**真值**。

## 1. 纪律（补丁四条，必须遵守）

1. **最小**：只加**必要**的接口/字段，**不改**既有 API 的签名与语义（既有 175 条工具的行为**必须逐字节不变**）。
2. **朝上游形状**：命名/放置/注释风格与所在文件一致；`PROPERTY_*`/`ClassDB` 暴露（若需要）按引擎既有写法；
   有 `_bind_methods` 的地方按既有模式注册。
3. **附「为什么需要」**：在**源码注释**里写清「这是为了上层能区分『编译失败』与『没结论』」，
   并在报告里给出完整的**补丁清单**（文件 / 行 / 新增符号 / 为什么）——我会把它落进 `DESIGN-DETAIL`。
4. **可被门覆盖**：新增行为必须有 **doctest**（`[MCPServer]*` 门③）与**线上证据**（门②），并在门④ 全量回归中不回归。

## 2. 要做的（**先做引擎源码调研，再决定补丁面**）

1. **调研并给出 `文件:行` 依据**：C# 编译在编辑器里**究竟由谁执行、结论落在哪**（`modules/mono/**`、
   `GodotTools` 的 Build 管道 / `BuildManager` / MSBuild 输出捕获、`CSharpLanguage`、`ScriptManagerBridge`）。
   必须回答：**「某个 `.cs` 文件的编译错误」这一事实在引擎/插件里**存在于何处**（或**根本不存在**、只在 C# 侧的过程里被打印过）。
2. **选择最小可行补丁面**（按此优先级，写到报告里）：
   - **(a) 文件级真值**：能把**每个 `.cs` 文件**的编译结论（ok / 有错误 + 诊断文本）读出来 → 首选；
   - **(b) 程序集级真值**：只能知道「**包含该文件的程序集构建失败**」→ 也可以接受，
     但工具回答必须**如实**表述为**项目/程序集级**（不得冒充文件级）；
   - **(c) 若连 (b) 都要改动 C# 插件的构建流程太大** → 退一步：**让 `reload()` 不再对「源文件与已加载程序集不一致」的情况报 OK**
     （即检测「该文件自上次成功构建后被改过」→ 返回错误/暴露标志），工具据此答
     「**尚未编译**（不是有效，也不是编译失败）」——**这也比现在谎称有效好**。
   **把你选了哪条、为什么、代价多大写清**；**若干条同时可行，选最小且最诚实的那条**。
3. **让工具用上真值**：`project_validate_script` / `project_validate_scripts` 的 C# 分类改为**真结论**
   （`ok` / `invalid` + `error_text` / 若仍无结论则保留 `unverifiable` **但必须说明为什么**）；
   **两个工具口径必须一致**；契约描述同步澄清（`DESCRIPTION_OVERRIDES` append + 重生成 + 指纹 + 门① 逐字）。
4. **证据（缺一不可）**：
   - ①**语法错误的 `.cs` → 明确失败**（给出**真实诊断文本**或项目级构建失败的真值）；
   - ②**合法 `.cs` → 明确通过**；
   - ③**「改过但还没编译」的状态**若存在，必须与「编译失败」**区分**（给证据）；
   - ④**非 mono 构建**下语言不可用仍走 `-32000`（TASK-050 口径**不变**，给前后对照）；
   - ⑤**既有 175 条工具行为不变**：`pre`（补丁前）/`post` 两二进制对同一批探针的响应**逐字节相同**（含全量 `tools/list`）。
     （注意：`tools/list` 里 C# 相关**描述**若改了，这属于**契约描述变更**——把该差异**单独列出**，不要混进"行为不变"的结论里。）
